Gin Gonic TutorialUpdated for Gin 1.12+ / Go 1.25+

REST APIs, form validation, templ components, and Datastar SSE

Updated from the original Gin-Gonic v1 tutorial. This version keeps the beginner-friendly flow, refreshes commands and examples, and adds production-style patterns for server-rendered Go applications.

1. What changed in this update

  • Uses current Gin documentation style and modern Go module setup.
  • Assumes Go 1.25+ for the quickstart because the current Gin quickstart lists Go 1.25 or above as a prerequisite.
  • Shows Gin 1.12+ installation using go get github.com/gin-gonic/gin@latest.
  • Expands binding and validation with JSON, form, URI, query, custom validators, and friendly error responses.
  • Adds templ for type-safe HTML components instead of relying only on html/template.
  • Adds Datastar with Server-Sent Events (SSE) for backend-driven interactivity without a large JavaScript framework.
  • Adds project structure, testing, graceful shutdown, security notes, and production checklist.

2. Sources and compatibility notes

Area

Current note

Gin

Gin remains a high-performance Go HTTP framework with routing, middleware, binding, validation, rendering, route groups, testing support, and trusted proxy settings.

Go version

The current Gin quickstart says Gin requires Go 1.25 or above.

Validation

Gin uses go-playground/validator/v10 for field-level validation. Prefer ShouldBind* when you want custom error responses.

templ is a separate Go HTML component tool. You write .templ files, then run templ generate to produce Go code.

Datastar

Datastar uses data-* attributes and backend SSE events to patch elements, patch signals, redirect, and execute scripts.

5. Gin quickstart

package main
import (
    "net/http"
    "github.com/gin-gonic/gin"
)
func main() {
    r := gin.Default()
    r.GET("/ping", func(c *gin.Context) {
        c.JSON(http.StatusOK, gin.H{"message": "pong"})

    // Default: listens on :8080 unless PORT is configured by your environment.
    _ = r.Run(":8080")
}

7. Binding and validation

Binding converts request data into a Go struct. Validation checks struct tags. The important practical rule is: use ShouldBind*, not Bind*, when you want to control the response body, status code, or template fragment returned to the user.

Use case

Recommended method

JSON body

c.ShouldBindJSON(&input)

HTML form

c.ShouldBind(&input) or c.ShouldBindWith(&input, binding.Form)

Query only

c.ShouldBindQuery(&input)

Path params

c.ShouldBindUri(&input)

Headers

c.ShouldBindHeader(&input)

Body reused more than once

c.ShouldBindBodyWith(&input, binding.JSON)

User form with validation tags 

package forms
type CreateUserInput struct {
    Name     string `form:"name" json:"name" binding:"required,min=2,max=80"`
    Email    string `form:"email" json:"email" binding:"required,email"`
    Password string `form:"password" json:"password" binding:"required,min=8"`
    Role     string `form:"role" json:"role" binding:"required,oneof=user admin"`
}
type UserURI struct {
    ID string `uri:"id" binding:"required,uuid"`
}

API handler with JSON validation 

func createUserAPI(c *gin.Context) {
    var input forms.CreateUserInput
    if err := c.ShouldBindJSON(&input); err != nil {
        c.JSON(http.StatusUnprocessableEntity, gin.H{
            "message": "Please fix the highlighted fields.",
            "errors":  validationErrors(err),
        })
        return
    }
    c.JSON(http.StatusCreated, gin.H{
        "message": "User created",
        "user": gin.H{"name": input.Name, "email": input.Email, "role": input.Role},
    })
}

Friendly validation errors

package forms
import (
    "errors"
    "strings"
    "github.com/go-playground/validator/v10"
)
type FieldError struct {
    Field   string `json:"field"`
    Message string `json:"message"`
}
func ValidationErrors(err error) []FieldError {
    var ve validator.ValidationErrors
    if !errors.As(err, &ve) {
        return []FieldError{{Field: "_", Message: err.Error()}}
    }
    out := make([]FieldError, 0, len(ve))
    for _, fe := range ve {
        field := strings.ToLower(fe.Field())
        msg := "Invalid value"
        switch fe.Tag() {
        case "required":
            msg = "This field is required"
        case "email":
            msg = "Enter a valid email address"
        case "min":
            msg = "Must be at least " + fe.Param() + " characters"
        case "max":
            msg = "Must be at most " + fe.Param() + " characters"
        case "oneof":
            msg = "Must be one of: " + fe.Param()
        }
        out = append(out, FieldError{Field: field, Message: msg})
    }
    return out
}

8. Custom validators

package forms
import (
    "time"
    "github.com/gin-gonic/gin/binding"
    "github.com/go-playground/validator/v10"
)
type BookingInput struct {
    CheckIn  time.Time `form:"check_in" binding:"required,bookabledate" time_format:"2006-01-02"`
    CheckOut time.Time `form:"check_out" binding:"required,gtfield=CheckIn" time_format:"2006-01-02"`
}
func RegisterValidators() {
    if v, ok := binding.Validator.Engine().(*validator.Validate); ok {
        _ = v.RegisterValidation("bookabledate", func(fl validator.FieldLevel) bool {
            date, ok := fl.Field().Interface().(time.Time)
            return ok && !time.Now().After(date)
        })
    }
}
func main() {
    forms.RegisterValidators()
    r := gin.Default()
    r.GET("/bookings/check", checkBooking)
    _ = r.Run(":8080")
}

9. templ templating with Gin

Gin has built-in html/template rendering, but templ gives you typed Go components. This is useful when you want reusable layouts, form components, and fragments that can be rendered as full pages or SSE/Datastar patches.

Basic templ component

            <title>{ title }</title>
            <link rel="stylesheet" href="/static/app.css"/>

        </head>
        <body>
            <main class="container">
                { children... }
            </main>
        </body>
    </html>
}

Render templ from Gin

package handlers
import (
    "net/http"
    "github.com/a-h/templ"
    "github.com/gin-gonic/gin"
)
func Render(c *gin.Context, status int, component templ.Component) {
    c.Status(status)
    c.Header("Content-Type", "text/html; charset=utf-8")
    if err := component.Render(c.Request.Context(), c.Writer); err != nil {
        c.Error(err)
    }
}
func NewUserPage(c *gin.Context) {
    Render(c, http.StatusOK, views.UsersPage(forms.CreateUserInput{}, map[string]string{}))
}

10. HTML form validation with Gin + templ 

func createUserPage(c *gin.Context) {
    var input forms.CreateUserInput
    if err := c.ShouldBind(&input); err != nil {
        errorMap := forms.ValidationErrorMap(err)
        Render(c, http.StatusUnprocessableEntity, views.UsersPage(input, errorMap))
        return
    }
    // Save to database here.
    c.Redirect(http.StatusSeeOther, "/users?created=1")
}
func ValidationErrorMap(err error) map[string]string {
    result := map[string]string{}
    for _, e := range ValidationErrors(err) {
        result[e.Field] = e.Message
    }
    return result
}

11. Datastar with Gin and SSE

Datastar adds interactivity with HTML attributes and SSE responses. Instead of returning JSON and writing frontend state management, your Gin endpoint streams instructions that patch HTML or signals in the browser.

Datastar mental model

Concept

Meaning

Signal

Small reactive state stored in the browser, such as {email: ""}.

Action

A data-on-* or data-*-sse attribute that calls the backend.

SSE response

A text/event-stream response that tells Datastar to patch elements, patch signals, redirect, or run scripts.

Patch element

Replace, append, prepend, remove, or morph a selected DOM element.

// internal/views/datastar.templ

package views
templ DatastarCounter() {
    @Layout("Datastar Counter") {
        <section id="counter" data-signals="{count: 0}">
            <h1>Counter</h1>
            <p>Current count: <strong data-text="$count"></strong></p>
            <button data-on-click={ "@post('/datastar/increment')" }>Increment</button>
        </section>
    }
}

Simple manual SSE response

func incrementManualSSE(c *gin.Context) {
    c.Header("Content-Type", "text/event-stream")
    c.Header("Cache-Control", "no-cache")
    c.Header("Connection", "keep-alive")
    // Datastar SSE events are text/event-stream messages.
    // Prefer the official SDK for production formatting.
    c.Writer.WriteString("event: datastar-patch-signals
")
    c.Writer.WriteString("data: signals {"count": 1}
")
    c.Writer.Flush()
}

Datastar Go SDK pattern

import (
    datastar "github.com/starfederation/datastar-go/datastar"
)
func incrementSSE(c *gin.Context) {
    sse := datastar.NewSSE(c.Writer, c.Request)
    // Send a signal patch. Exact helper names may change by SDK version;
    // check pkg.go.dev for the installed version.
    _ = sse.PatchSignals([]byte(`{"count": 1}`))
}
func patchUserForm(c *gin.Context) {
    sse := datastar.NewSSE(c.Writer, c.Request)
    html := `<div id="notice" class="success">Saved!</div>`
    _ = sse.PatchElements(html)
}

SDK APIs can move while Datastar is still evolving. The durable pieces are the HTTP contract: Content-Type text/event-stream and Datastar SSE events for patching signals/elements. Use the SDK matching your installed module version.

12. Full example: live validated form with Datastar SSE

// internal/views/live_user_form.templ

package views
import "example.com/gin-modern-tutorial/internal/forms"
templ LiveUserForm(input forms.CreateUserInput, errors map[string]string) {
    <form id="user-form" data-on-submit={ "@post('/users/live')" }>
        <input name="name" placeholder="Name" value={ input.Name } />
        if errors["name"] != "" { <p class="error">{ errors["name"] }</p> }
        <input name="email" placeholder="Email" value={ input.Email } />
        if errors["email"] != "" { <p class="error">{ errors["email"] }</p> }
        <input type="password" name="password" placeholder="Password" />
        if errors["password"] != "" { <p class="error">{ errors["password"] }</p> }
        <input name="role" value="user" type="hidden" />
        <button>Create</button>
    </form>
}
templ LiveUsersPage(input forms.CreateUserInput, errors map[string]string) {
    @Layout("Live users") {
        <h1>Live users</h1>
        <div id="form-panel">
            @LiveUserForm(input, errors)
        </div>
        <div id="notice"></div>
    }
}
func liveUserSubmit(c *gin.Context) {
    var input forms.CreateUserInput
    if err := c.ShouldBind(&input); err != nil {
        html := renderToString(c.Request.Context(), views.LiveUserForm(input, forms.ValidationErrorMap(err)))
        sendDatastarPatch(c, "#form-panel", html)
        return
    }
    // Save user here.
    sendDatastarPatch(c, "#notice", `<div id="notice" class="success">User created.</div>`)
}
func renderToString(ctx context.Context, cmp templ.Component) string {
    var b bytes.Buffer
    _ = cmp.Render(ctx, &b)
    return b.String()
}
func sendDatastarPatch(c *gin.Context, selector string, html string) {
    c.Header("Content-Type", "text/event-stream")
    c.Header("Cache-Control", "no-cache")
    c.Header("Connection", "keep-alive")
    // Use the official Datastar SDK in real code. This helper is shown
    // to make the SSE shape easy to understand.
    fmt.Fprintf(c.Writer, "event: datastar-patch-elements
")
    fmt.Fprintf(c.Writer, "data: selector %s
", selector)
    fmt.Fprintf(c.Writer, "data: elements %s
", html)
    c.Writer.Flush()
}

13. Middleware and groups

func requestID() gin.HandlerFunc {
    return func(c *gin.Context) {
        id := c.GetHeader("X-Request-ID")
        if id == "" {
            id = uuid.NewString()
        }
        c.Header("X-Request-ID", id)
        c.Set("requestID", id)
        c.Next()
    }
}
func setupRouter() *gin.Engine {
    r := gin.New()
    r.Use(gin.Logger(), gin.Recovery(), requestID())
    r.Static("/static", "./static")
    api := r.Group("/api")
    api.POST("/users", createUserAPI)
    pages := r.Group("")
    pages.GET("/users/new", NewUserPage)
    pages.POST("/users", createUserPage)
    pages.POST("/users/live", liveUserSubmit)
    return r
}

14. File uploads

type ProfileForm struct {
    Name   string                `form:"name" binding:"required"`
    Avatar *multipart.FileHeader `form:"avatar" binding:"required"`
}
func uploadProfile(c *gin.Context) {
    var form ProfileForm
    if err := c.ShouldBind(&form); err != nil {
        c.JSON(422, gin.H{"errors": forms.ValidationErrors(err)})
        return
    }
    safeName := filepath.Base(form.Avatar.Filename)
    dst := filepath.Join("uploads", uuid.NewString()+"-"+safeName)
    if err := c.SaveUploadedFile(form.Avatar, dst); err != nil {
        c.JSON(500, gin.H{"message": "Upload failed"})
        return
    }
    c.JSON(201, gin.H{"path": dst})
}
  • Never trust file.Filename directly. Strip paths, generate server-side names, validate file type, and limit size.
  • Set router.MaxMultipartMemory for large forms and store large files outside the application container when deploying.

15. Testing Gin handlers

func TestPing(t *testing.T) {
    router := setupRouter()
    w := httptest.NewRecorder()
    req := httptest.NewRequest(http.MethodGet, "/ping", nil)
    router.ServeHTTP(w, req)
    require.Equal(t, http.StatusOK, w.Code)
    require.JSONEq(t, `{"message":"pong"}`, w.Body.String())
}
func TestCreateUserValidation(t *testing.T) {
    router := setupRouter()
    body := strings.NewReader(`{"name":"A","email":"bad","password":"x","role":"owner"}`)
    req := httptest.NewRequest(http.MethodPost, "/api/users", body)
    req.Header.Set("Content-Type", "application/json")
    w := httptest.NewRecorder()
    router.ServeHTTP(w, req)
    require.Equal(t, http.StatusUnprocessableEntity, w.Code)
}

16. Production server setup

func main() {
    gin.SetMode(gin.ReleaseMode)
    r := setupRouter()
    _ = r.SetTrustedProxies([]string{"203.0.113.10/8", "203.0.113.10/12"})
    srv := &http.Server{
        Addr:              ":8080",
        Handler:           r,
        ReadHeaderTimeout: 5 * time.Second,
        ReadTimeout:       15 * time.Second,
        WriteTimeout:      30 * time.Second,
        IdleTimeout:       60 * time.Second,
        MaxHeaderBytes:    1 << 20,
    }
    go func() {
        if err := srv.ListenAndServe(); err != nil && !errors.Is(err, http.ErrServerClosed) {
            log.Fatal(err)
        }
    }()
    quit := make(chan os.Signal, 1)
    signal.Notify(quit, syscall.SIGINT, syscall.SIGTERM)
    <-quit
    ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
    defer cancel()
    _ = srv.Shutdown(ctx)
}

17. Security checklist

  • Use ShouldBind* and return 422 for validation errors instead of leaking raw parser errors to users.
  • Set trusted proxies explicitly when behind Nginx, Traefik, Caddy, Cloudflare, Fly.io, or Kubernetes ingress.
  • Use CSRF protection for cookie-authenticated HTML forms.
  • Use HttpOnly, Secure, SameSite cookies for sessions.
  • Escape output by using templ or html/template; avoid template.HTML unless content is trusted.
  • Limit body size and multipart memory; validate uploads by MIME sniffing and business rules.
  • Set timeouts on http.Server.
  • Centralize error logging and avoid returning stack traces.
  • For Datastar SSE, authenticate endpoints the same way as normal POST routes and validate all incoming signals/forms.

20. Migration notes from the old tutorial

  • The old examples still teach important basics: routes, path params, query params, forms, uploads, route groups, middleware, rendering, cookies, trusted proxies, and testing.
  • Prefer modern Go modules over GOPATH-era workflows.
  • Prefer ShouldBind* for almost every real application because it lets you choose JSON, HTML, or SSE validation responses.
  • For frontend pages, templ components are easier to refactor than string-based templates and work well for Datastar fragments.
  • For live UI, Datastar SSE lets your Gin handlers stream DOM updates without converting the page into a SPA.
