Go Language Documentation

Modern Go development is module-first. You normally create a project folder anywhere, run `go mod init`, and let the Go tool manage dependencies through `go.mod` and `go.sum`.

* Use modules, not GOPATH/src, for almost every new project.
* Use go install package@version to install command-line tools.
* Use go get only to add, upgrade, or downgrade module dependencies.
* Use go work for local multi-module development; do not treat it as a production dependency manager.

1. Installation and Environment

Install Go from the official Go downloads page or a trusted package manager. After installation, verify the version and environment variables:

go version
go env GOROOT GOPATH GOMOD GOWORK

Modern projects do not need to live under GOPATH. GOPATH is still used for the module cache and binaries installed by go install, but your source code can be anywhere. Ensure your binary path is exported: 

export PATH="$PATH:$(go env GOPATH)/bin"

Useful Environment Commands:

go env # Print Go environment
go env -w GOPRIVATE=github.com/your-org/ # Private modules configurations
go env -w GOTOOLCHAIN=auto # Allow automatic toolchain selection

4. Packages, Imports, and Visibility

    "fmt"

Unexported: Start with a lowercase letter (user, newServer).

internal/ packages can only be imported by code inside that specific parent directory tree.

The Loop Pre-Iteration Variable Fix

The Problem (Go 1.21 and earlier)

Historically, Go reused the exact same memory address for the loop iteration variable across every iteration loop execution. If you passed a pointer of the loop variable, or captured it inside a closure (such as a goroutine or an event callback), every single reference wound up pointing to the final mutated value of the loop.

The Modern Fix (Go 1.22+)

Since Go 1.22, loop variables created by for loops are per-iteration variables. This prevents accidental closure bugs in goroutines and callbacks natively without requiring manual semantic workarounds.

Comparison Example

package main

import (
	"fmt"
	"sync"
)

func main() {
	items := []string{"A", "B", "C"}
	var wg sync.WaitGroup

	// --- STANDARD LOOP CONCURRENCY ---
	// In Go 1.21 and below, this would likely print "C", "C", "C".
	// In Go 1.22 through Go 1.26+, this correctly prints "A", "B", "C" (unordered).
	fmt.Println("--- Modern Loop Semantics ---")
	for _, item := range items {
		wg.Add(1)
		go func() {
			defer wg.Done()
			fmt.Println(item) 
		}()
	}
	wg.Wait()

	// --- MANUAL PRE-ITERATION FIX (For Legacy Contexts) ---
	// What it fixes: Manually shadowing/redefining the variable inside the block 
	// forces a unique memory reference per block execution context in old compilers.
	fmt.Println("\n--- Manual Pre-iteration Variable Fix (Legacy) ---")
	for _, item := range items {
		wg.Add(1)
		itemFixed := item // Explicit allocation capture
		go func() {
			defer wg.Done()
			fmt.Println(itemFixed)
		}()
	}
	wg.Wait()
}

Explicit Errors

Go handles exceptions using explicit value errors. Wrap contextual errors with %w and inspect them using errors.Is or errors.As: 

var ErrNotFound = errors.New("not found")

func load(id string) (User, error) {
    if id == "" {
        return User{}, fmt.Errorf("load user: %w", ErrNotFound)
    }
    return User{}, nil
}

// errors.Is example
user, err := load(id)
if errors.Is(err, ErrNotFound) {
    // Handle specific not found branch
}
if err != nil {
    return fmt.Errorf("handler failed: %w", err)
}
// errors.As example
type ValidationError struct {
	Field string
	Msg   string
}
func (e *ValidationError) Error() string {
	return e.Field + ": " + e.Msg
}
func createUser() error {
	return fmt.Errorf(
		"create user failed: %w",
		&ValidationError{
			Field: "email",
			Msg:   "invalid email",
		},
	)
}
err := createUser()
var validationErr *ValidationError
if errors.As(err, &validationErr) {
	fmt.Println("Field:", validationErr.Field)
	fmt.Println("Message:", validationErr.Msg)
}


Note:

errors.Is - Compare against a known error value

errors.As - Find/extract an error of a particular type

Use panic only for programmer blunders or unrecoverable system initialization errors—never basic bad data or user inputs.

10. Generics

Generics parameterize functions and structures across a defined set of compatible types. 

type Number interface {
    ~int | ~int64 | ~float64
}

// Generic validation algorithm
func Sum[T Number](values []T) T {
    var total T
    for _, v := range values {
        total += v
    }
    return total
}

// Generic Data Structure Struct
type Pair[T any] struct {
    First  T
    Second T
}

// Type constraint transformations
func MapKeys[K comparable, V any](m map[K]V) []K {
    keys := make([]K, 0, len(m))
    for k := range m {
        keys = append(keys, k)
    }
    return keys
}

Advanced Generic Pattern: Generic Chainable Methods (Builder Pattern)

By using generic parameters, you can write types that provide a fluent, chainable API for any data structure while ensuring static type check safety at compilation time. 

package main

import "fmt"

// Stream provides fluent chaining over slice collections of type T
type Stream[T any] struct {
	items []T
}

func NewStream[T any](items []T) *Stream[T] {
	return &Stream[T]{items: items}
}

// Filter chains down slices based on matching conditional predicates
func (s *Stream[T]) Filter(predicate func(T) bool) *Stream[T] {
	var filtered []T
	for _, item := range s.items {
		if predicate(item) {
			filtered = append(filtered, item)
		}
	}
	s.items = filtered
	return s
}

// Collect terminates the chain and unloads the current state
func (s *Stream[T]) Collect() []T {
	return s.items
}

func main() {
	numbers := []int{10, 15, 20, 25, 30}
	
	result := NewStream(numbers).
		Filter(func(n int) bool { return n > 12 }).
		Filter(func(n int) bool { return n%2 == 0 }).
		Collect()

	fmt.Println(result) // Output: [20 30]
}

Structured Concurrency with errgroup (wg.Go)

Standard sync.WaitGroup coordinates structural timing but does not handle error cascades or context cancellations out of the box. Using golang.org/x/sync/errgroup handles tracking tasks using a functional execution model .Go(), catching errors, and forwarding cross-context shutdowns automatically. 

package main

import (
	"context"
	"fmt"
	"net/http"
	"time"

	"golang.org/x/sync/errgroup"
)

func main() {
	// WithContext builds a derived context canceled automatically if any step reports an error
	g, ctx := errgroup.WithContext(context.Background())

	urls := []string{
		"https://httpbin.org/delay/l",
		"https://httpbin.org/status/404", // This causes an error path
		"https://httpbin.org/delay/2",
	}

	for _, url := range urls {
		// Launch tasks concurrently via .Go()
		g.Go(func() error {
			req, err := http.NewRequestWithContext(ctx, http.MethodGet, url, nil)
			if err != nil {
				return err
			}

			client := &http.Client{Timeout: 5 * time.Second}
			resp, err := client.Do(req)
			if err != nil {
				return err
			}
			defer resp.Body.Close()

			if resp.StatusCode >= 400 {
				return fmt.Errorf("http error on %s: status %d", url, resp.StatusCode)
			}

			fmt.Printf("Fetched %s\n", url)
			return nil
		})
	}

	// Wait handles synchronizations and returns the first recorded non-nil error
	if err := g.Wait(); err != nil {
		fmt.Printf("Execution halted with group error: %v\n", err)
	} else {
		fmt.Println("All fetches resolved nicely!")
	}
}

Hello World

package main

Values

Go has various value types including strings, integers, floats, and booleans. Here are a few basic examples. 

package main

import "fmt"

func main() {
    fmt.Println("go" + "lang")
    fmt.Println("1+1 =", 1+1)
    fmt.Println("7.0/3.0 =", 7.0/3.0)
    fmt.Println(true && false)
    fmt.Println(true || false)
    fmt.Println(!true)

Variables

In Go, variables are explicitly declared. The compiler uses the type to check correctness of function calls. var declares variables; := is shorthand for declare-and-initialize inside functions. 

package main

import "fmt"

func main() {
    var a = "initial"
    fmt.Println(a)

    var b, c int = 1, 2
    fmt.Println(b, c)

    var d = true
    fmt.Println(d)

    var e int
    fmt.Println(e) // zero-valued: 0

    f := "apple" // short declaration
    fmt.Println(f)
}

Constants

Go supports constants of character, string, boolean, and numeric values. const declares a constant value that cannot be changed after assignment. Constants can appear anywhere a var can but with the const keyword. 

package main

import (
    "fmt"
    "math"
)

const s string = "constant"

func main() {
    fmt.Println(s)
    const n = 500000000
    const d = 3e20 / n
    fmt.Println(d)
    fmt.Println(int64(d))
    fmt.Println(math.Sin(n))
}

Control Flow & Loop Scope Mechanics

For

for is Go's only looping construct. It covers traditional for, while, and infinite loops — there is no while keyword. 

package main

import "fmt"

func main() {
    // Classic: init; condition; post
    i := 1
    for i <= 3 {
        fmt.Println(i)
        i = i + 1
    }

    // Traditional for
    for j := 0; j < 3; j++ {
        fmt.Println(j)
    }

    // Infinite loop with break
    for {
        fmt.Println("loop")
        break
    }

    // Continue to next iteration
    for n := 0; n < 6; n++ {
        if n%2 == 0 {
            continue
        }
        fmt.Println(n)
    }
}

If/Else

Branching with if and else. Parentheses are not needed around conditions, but braces are required. You can put a short statement before the condition — its variables are scoped to the if/else block. 

package main

import "fmt"

func main() {
    if 7%2 == 0 {
        fmt.Println("7 is even")
    } else {
        fmt.Println("7 is odd")
    }

    if 8%4 == 0 {
        fmt.Println("8 is divisible by 4")
    }

    // Statement before condition
    if num := 9; num < 0 {
        fmt.Println(num, "is negative")
    } else if num < 10 {
        fmt.Println(num, "has 1 digit")
    } else {
        fmt.Println(num, "has multiple digits")
    }
}

Switch

Switch statements express conditionals across many branches. Go's switch is cleaner than C's: it doesn't need break statements and cases don't fall through by default. 

package main

import (
    "fmt"
    "time"
)

func main() {
    i := 2
    switch i {
    case 1:
        fmt.Println("one")
    case 2:
        fmt.Println("two")
    case 3:
        fmt.Println("three")
    }

    // Switch on time
    switch time.Now().Weekday() {
    case time.Saturday, time.Sunday:
        fmt.Println("It's the weekend")
    default:
        fmt.Println("It's a weekday")
    }

    // Switch without an expression (like if/else chain)
    t := time.Now()
    switch {
    case t.Hour() < 12:
        fmt.Println("Before noon")
    default:
        fmt.Println("After noon")
    }
}

Functions, Defer, and Error Handling

Functions

Functions are central in Go. They are defined with func and can take zero or more arguments and return zero or more values. 

package main

import "fmt"

func plus(a int, b int) int {
    return a + b
}

func plusPlus(a, b, c int) int {
    return a + b + c
}

func main() {
    res := plus(1, 2)
    fmt.Println("1+2 =", res)

    res = plusPlus(1, 2, 3)
    fmt.Println("1+2+3 =", res)
}

Multiple Return Values

Go has built-in support for multiple return values. This is used idiomatically to return both result and error values from a function. 

package main

import "fmt"

func vals() (int, int) {
    return 3, 7
}

func main() {
    a, b := vals()
    fmt.Println(a)
    fmt.Println(b)

    // Use _ to ignore a return value
    _, c := vals()
    fmt.Println(c)
}

Variadic Functions

Variadic functions can be called with any number of trailing arguments. fmt.Println is a common variadic function. 

package main

import "fmt"

func sum(nums ...int) {
    fmt.Print(nums, " ")
    total := 0
    for _, num := range nums {
        total += num
    }
    fmt.Println(total)
}

func main() {
    sum(1, 2)
    sum(1, 2, 3)

    nums := []int{1, 2, 3, 4}
    sum(nums...) // spread a slice
}

Closures

Go supports anonymous functions, which can form closures. Anonymous functions are useful when you want to define a function inline without naming it. A closure captures variables from its surrounding scope. 

package main

import "fmt"

func intSeq() func() int {
    i := 0
    return func() int {
        i++
        return i
    }
}

func main() {
    nextInt := intSeq()
    fmt.Println(nextInt()) // 1
    fmt.Println(nextInt()) // 2
    fmt.Println(nextInt()) // 3

    newInts := intSeq()
    fmt.Println(newInts()) // 1 — fresh closure
}

Recover

recover catches a panic and resumes normal execution. It must be called inside a deferred function. This is useful for libraries that shouldn't crash the caller on unexpected errors.

Custom Errors

You can create custom error types by implementing the error interface (which requires only an Error() string method). Custom errors let callers inspect error details using type assertions or errors.As. 

package main

    "errors"
    "fmt"

    Arg     int
    Message string
}

}

Pointers

Go supports pointers, allowing you to pass references to values and records within your program. A pointer holds the memory address of a value. The & operator generates a pointer to its operand, and the * operator dereferences a pointer.

    fmt.Println("pointer:", &i)
}

Strings and Runes

A Go string is a read-only slice of bytes. The language and standard library treat strings specially — as containers of text encoded in UTF-8. A rune is an alias for int32 and represents a Unicode code point.

Go supports methods defined on struct types. A method is a function with a special receiver argument. You can define methods with pointer receivers (to mutate state) or value receivers (read-only).

Enums

Go doesn't have a dedicated enum keyword but uses typed constants with iota to create enumerated types. This pattern gives you type safety and auto-incrementing values.

type ServerState int

const (
    StateIdle ServerState = iota
    StateConnected
    StateError
    StateRetrying
)

// Implement the Stringer interface for readable output
func (ss ServerState) String() string {
    switch ss {
    case StateIdle:
        return "idle"
    case StateConnected:
        return "connected"
    case StateError:
        return "error"
    case StateRetrying:
        return "retrying"
    default:
        return fmt.Sprintf("unknown(%d)", ss)
    }
}

func transition(s ServerState) ServerState {
    switch s {
    case StateIdle:
        return StateConnected
    case StateConnected, StateRetrying:
        return StateIdle
    case StateError:
        return StateRetrying
    default:
        panic(fmt.Sprintf("unknown state: %s", s))
    }
}

Struct Embedding

Go supports embedding of structs and interfaces to express a more seamless composition of types. This is not inheritance — it's composition where the embedded type's methods are promoted to the embedding struct. 

package main

    num int
}

}

type container struct {
    base
    str string
}

    fmt.Println("describe:", co.describe())

        describe() string

Generics

Generics

Starting with Go 1.18, the language supports generics via type parameters. This lets you write functions and types that work with multiple types while remaining type-safe at compile time. 

package main

import "fmt"

// MapKeys returns the keys of any map. The type parameters
// are specified in square brackets.
func MapKeys[K comparable, V any](m map[K]V) []K {
    r := make([]K, 0, len(m))
    for k := range m {
        r = append(r, k)
    }
    return r
}

// List is a generic singly-linked list
type List[T any] struct {
    head, tail *element[T]
}

type element[T any] struct {
    next *element[T]
    val  T
}

func (lst *List[T]) Push(v T) {
    if lst.tail == nil {
        lst.head = &element[T]{val: v}
        lst.tail = lst.head
    } else {
        lst.tail.next = &element[T]{val: v}
        lst.tail = lst.tail.next
    }
}

func (lst *List[T]) GetAll() []T {
    var elems []T
    for e := lst.head; e != nil; e = e.next {
        elems = append(elems, e.val)
    }
    return elems
}

func main() {
    var m = map[int]string{1: "2", 2: "4", 4: "8"}
    fmt.Println("keys:", MapKeys(m))

    lst := List[int]{}
    lst.Push(10)
    lst.Push(13)
    lst.Push(23)
    fmt.Println("list:", lst.GetAll())
}

Range over Iterators

Starting with Go 1.23, you can use range over custom iterator functions. An iterator is a function that takes a yield callback and calls it for each element. This enables for...range syntax over any sequence.

Worker Pools

A worker pool is a common concurrency pattern: a fixed number of goroutines process jobs from a shared channel. This limits concurrency while keeping throughput high. 

package main

import (
    "fmt"
    "time"
)

func worker(id int, jobs <-chan int, results chan<- int) {
    for j := range jobs {
        fmt.Println("worker", id, "started  job", j)
        time.Sleep(time.Second)
        fmt.Println("worker", id, "finished job", j)
        results <- j * 2
    }
}

func main() {
    const numJobs = 5
    jobs := make(chan int, numJobs)
    results := make(chan int, numJobs)

    for w := 1; w <= 3; w++ {
        go worker(w, jobs, results)
    }

    for j := 1; j <= numJobs; j++ {
        jobs <- j
    }
    close(jobs)

    for a := 1; a <= numJobs; a++ {
        <-results

WaitGroups

A sync.WaitGroup waits for a collection of goroutines to finish. Add to the counter before launching, call Done when each finishes, and Wait blocks until the counter is zero. 

package main

import (
    "fmt"
    "sync"
    "time"
)

func workerWG(id int) {
    fmt.Printf("Worker %d starting\n", id)
    time.Sleep(time.Second)
    fmt.Printf("Worker %d done\n", id)
}

func main() {
    var wg sync.WaitGroup

    for i := 1; i <= 5; i++ {
        wg.Add(1)
        go func(id int) {
            defer wg.Done()
            workerWG(id)
        }(i)
    }
    wg.Wait()
}

Rate Limiting

Rate limiting is an important mechanism for controlling resource utilization and maintaining quality of service. Go supports rate limiting with goroutines, channels, and tickers. 

package main

import (
    "fmt"
    "time"
)

func main() {
    requests := make(chan int, 5)
    for i := 1; i <= 5; i++ {
        requests <- i
    }
    close(requests)

    limiter := time.Tick(200 * time.Millisecond)

    for req := range requests {
        <-limiter
        fmt.Println("request", req, time.Now())
    }

    // Bursty limiter: allow short bursts
    burstyLimiter := make(chan time.Time, 3)
    for i := 0; i < 3; i++ {
        burstyLimiter <- time.Now()
    }
    go func() {
        for t := range time.Tick(200 * time.Millisecond) {
            burstyLimiter <- t
        }
    }()

    burstyRequests := make(chan int, 5)
    for i := 1; i <= 5; i++ {
        burstyRequests <- i
    }
    close(burstyRequests)
    for req := range burstyRequests {
        <-burstyLimiter
        fmt.Println("request", req, time.Now())

Stateful Goroutines

An alternative to mutexes: use a single goroutine that owns the state, and communicate via channels. This is the "share memory by communicating" approach. 

package main

import (
    "fmt"
    "math/rand"
    "sync/atomic"
    "time"
)

type readOp struct {
    key  int
    resp chan int
}
type writeOp struct {
    key  int
    val  int
    resp chan bool
}

func main() {
    var readOps, writeOps atomic.Uint64
    reads := make(chan readOp)
    writes := make(chan writeOp)

    // State-owning goroutine
    go func() {
        state := make(map[int]int)
        for {
            select {
            case read := <-reads:
                read.resp <- state[read.key]
            case write := <-writes:
                state[write.key] = write.val
                write.resp <- true
            }
        }
    }()

    // 100 reads
    for r := 0; r < 100; r++ {
        go func() {
            for {
                read := readOp{key: rand.Intn(5), resp: make(chan int)}
                reads <- read
                <-read.resp
                readOps.Add(1)
                time.Sleep(time.Millisecond)
            }
        }()
    }
    // 10 writes
    for w := 0; w < 10; w++ {
        go func() {
            for {
                write := writeOp{key: rand.Intn(5), val: rand.Intn(100), resp: make(chan bool)}
                writes <- write
                <-write.resp
                writeOps.Add(1)
                time.Sleep(time.Millisecond)
            }
        }()
    }

    time.Sleep(time.Second)
    fmt.Println("readOps:", readOps.Load())
    fmt.Println("writeOps:", writeOps.Load())
}

Channels

Channels are the pipes that connect concurrent goroutines. You can send values into channels from one goroutine and receive those values in another. By default, sends and receives block until both sides are ready, enabling synchronization without locks. 

package main

import "fmt"

func main() {
    // Create a new channel with make(chan val-type)
    messages := make(chan string)

    // Send a value into a channel from a goroutine
    go func() {
        messages <- "ping"
    }()

    // Receive a value from the channel
    msg := <-messages
    fmt.Println(msg)

    // Buffered channels accept a limited number of values
    // without a corresponding receiver
    ch := make(chan int, 2)
    ch <- 1
    ch <- 2

    fmt.Println(<-ch)
    fmt.Println(<-ch)

    // Channels can be used for synchronization
    done := make(chan bool)
    go func() {
        fmt.Println("working...")
        done <- true
    }()
    <-done

}

func check(e error) { if e != nil { panic(e) } }

func main() {
    err := os.Mkdir("subdir", 0755)
    check(err)
    defer os.RemoveAll("subdir")

    createEmptyFile := func(name string) {
        check(os.WriteFile(name, []byte(""), 0644))
    }
    createEmptyFile("subdir/file1")

    os.MkdirAll("subdir/parent/child", 0755)
    createEmptyFile("subdir/parent/file2")
    createEmptyFile("subdir/parent/child/file4")

    c, _ := os.ReadDir("subdir/parent")
    fmt.Println("Listing subdir/parent")
    for _, entry := range c {
        fmt.Println(" ", entry.Name(), entry.IsDir())
    }

    filepath.WalkDir("subdir", func(path string, d fs.DirEntry, err error) error {
        if err != nil { return err }
        fmt.Println(" ", path, d.IsDir())
        return nil
    })
}

Spawning Processes

Sometimes a Go program needs to spawn other processes. os/exec runs external commands and captures their output. 

package main

import (
    "fmt"
    "os/exec"
)

func main() {
    // Simple command
    out, err := exec.Command("date").Output()
    if err != nil {
        panic(err)
    }
    fmt.Println("date:", string(out))

    // Command with args + piping
    grep := exec.Command("grep", "hello")
    grep.Stdin = nil
    grepIn, _ := grep.StdinPipe()
    grepOut, _ := grep.StdoutPipe()
    grep.Start()
    grepIn.Write([]byte("hello grep\ngoodbye grep"))
    grepIn.Close()
    grepBytes, _ := fmt.Println(grepOut)
    _ = grepBytes
    grep.Wait()
}

Exec'ing Processes

Sometimes we want to completely replace the current Go process with another. syscall.Exec does this (Unix only) — the Go program disappears and the new process takes over its PID. 

package main

import (
    "os"
    "os/exec"
    "syscall"
)

func main() {
    binary, err := exec.LookPath("ls")
    if err != nil {
        panic(err)
    }
    args := []string{"ls", "-a", "-l", "-h"}
    env := os.Environ()
    execErr := syscall.Exec(binary, args, env)
    if execErr != nil {
        panic(execErr)
    }
}

Signals

Go programs can handle Unix signals for graceful shutdown. The os/signal package notifies a channel when signals arrive. 

package main

import (
    "fmt"
    "os"
    "os/signal"
    "syscall"
)

func main() {
    sigs := make(chan os.Signal, 1)
    signal.Notify(sigs, syscall.SIGINT, syscall.SIGTERM)

    done := make(chan bool, 1)
    go func() {
        sig := <-sigs
        fmt.Println()
        fmt.Println("received:", sig)
        done <- true
    }()

    fmt.Println("awaiting signal (press Ctrl+C)")
    <-done
    fmt.Println("exiting")
}

HTTP Server

Writing a basic HTTP server in Go is straightforward. Handlers are functions with a standard signature. The server runs until stopped. 

package main

import (
    "fmt"
    "net/http"
)

func hello(w http.ResponseWriter, req *http.Request) {
    fmt.Fprintf(w, "hello\n")
}

func headers(w http.ResponseWriter, req *http.Request) {
    for name, headers := range req.Header {
        for _, h := range headers {
            fmt.Fprintf(w, "%v: %v\n", name, h)
        }
    }
}

func main() {
    http.HandleFunc("/hello", hello)
    http.HandleFunc("/headers", headers)
    fmt.Println("Listening on :8090")
    http.ListenAndServe(":8090", nil)
}

TCP Server

Go's net package provides low-level networking. Here's a TCP echo server that handles each connection in its own goroutine. 

package main

import (
    "fmt"
    "io"
    "net"
)

func handleConn(conn net.Conn) {
    defer conn.Close()
    io.Copy(conn, conn) // echo back
}

func main() {
    ln, err := net.Listen("tcp", ":9000")
    if err != nil {
        panic(err)
    }
    fmt.Println("TCP echo server on :9000")
    for {
        conn, err := ln.Accept()
        if err != nil {
            continue
        }
        go handleConn(conn)
    }
}

Command-Line Subcommands

Use flag.NewFlagSet for each subcommand, then parse based on os.Args[1]. 

package main

import (
    "flag"
    "fmt"
    "os"
)

func main() {
    fooCmd := flag.NewFlagSet("foo", flag.ExitOnError)
    fooEnable := fooCmd.Bool("enable", false, "enable")
    fooName := fooCmd.String("name", "", "name")

    barCmd := flag.NewFlagSet("bar", flag.ExitOnError)
    barLevel := barCmd.Int("level", 0, "level")

    if len(os.Args) < 2 {
        fmt.Println("expected 'foo' or 'bar' subcommands")
        os.Exit(1)
    }

    switch os.Args[1] {
    case "foo":
        fooCmd.Parse(os.Args[2:])
        fmt.Println("subcommand 'foo'")
        fmt.Println("  enable:", *fooEnable)
        fmt.Println("  name:", *fooName)
        fmt.Println("  tail:", fooCmd.Args())
    case "bar":
        barCmd.Parse(os.Args[2:])
        fmt.Println("subcommand 'bar'")
        fmt.Println("  level:", *barLevel)
        fmt.Println("  tail:", barCmd.Args())
    default:
        fmt.Println("expected 'foo' or 'bar' subcommands")
        os.Exit(1)
    }
}
